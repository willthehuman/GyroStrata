# GyroStrata on Strata v0.2.2 (Linux / CUDA)

A port of this repository's engine patch (written against Strata v0.1.45) onto Strata **v0.2.2**,
built and measured on Linux with CUDA. Published as `patches/strata-022.patch` so the reconstruction
stays reproducible the same way the v0.1.45 one is.

Measured on: RTX 4070 SUPER 12 GB, 31 GiB RAM, 6-core CPU (AVX2 only, no AVX-512), CUDA 13.3, sm_89,
Gyro-M (Qwen3.8-Flash-Next, TQ2_T experts, 512 experts x 48 layers).

## Applying and building

```sh
git clone https://github.com/Niko1221/Strata.git
cd Strata && git checkout v0.2.2
git apply --3way patches/strata-022.patch          # 15 files conflict, see below

cmake -B build -DCMAKE_BUILD_TYPE=Release -DSTRATA_ENABLE_CUDA=ON \
      -DCMAKE_CUDA_ARCHITECTURES=89 -DSTRATA_GGML_DIR=/path/to/llama.cpp
cmake --build build -j12
```

`STRATA_GGML_DIR` must be the **agentionai llama.cpp fork** (`dc255f2a4b6e4211b555b0c05260b2523281f314`).
Upstream ggml-org has no TQ2_T / TQK6 / TQK7 types, and v0.2.2's native pack path refuses the model
without them (`native experts: ggml-cpu has no dot product for type 145` / `expert geometry is not whole
blocks`). With the fork present, the trellis MMQ instances come from the fork's own
`mmq-instance-tqk6.cu` and `STRATA_MMQ_TQ=1` is set.

## Conflict resolutions

`git apply --3way` conflicts in 15 files, not four. v0.2.2 moved ahead of the v0.1.45 patch in most of
them, so v0.2.2 won wherever it is a superset and the patch's intent was re-applied on top.

- **`src/core/expert_source.cpp`** — v0.2.2's `STRATA_COLD_OVERLAP` state machine replaces the patch's
  Windows-only `STRATA_RESIDENT_IO_OVERLAP` / `AsyncJob` dispatch. The patch's `STRATA_FILE_SKIP`,
  `ram_heat` and `rebalance_ram` are ported onto it. Taking the v0.2.2 side leaves three dangling
  references (`prepare_jobs`, `ready_jobs`, `ready_ms`) that have to be reverted by hand.
- **`src/kernels/cuda/iq_kernels.cu`** — 13 conflicts, all v0.2.2 supersets: `STAGE_GRID` shared-memory
  LUT staging, the sub-16-row trellis kernels, 65535-row Hadamard slicing, `__ldg` word reads. The
  patch's `hadamard_rows_kernel` block is already in v0.2.2, and the 3-way merge **duplicates** it
  (17 lines defined twice, 5 nvcc errors) — the duplicate must be deleted.
- **`src/kernels/cpu/tq_avx2.cpp`** — the patch's `rows4<KB>` TQ2_T fast path is kept inside v0.2.2's
  load/broadcast/blend body; lane values are identical.
- **`src/kernels/cpu/tq_cpu.cpp` / `tq_cpu.hpp`, `native_expert.cpp`** — v0.2.2's `STRATA_TQ_X86` guards
  and `tq_rows_own()` policy are kept (they cover arm64 and the scalar-on-any-CPU case).
- **`CMakeLists.txt`** — v0.2.2's `STRATA_MMQ_TQ_OVERLAY` and `SKIP_RETURN_CODE 77` are kept; the
  `STRATA_MMQ_TQ=1` definition for the fork's instances is already present.
- The rest are comments and formatting; the v0.2.2 side is kept.

## Findings worth fixing upstream in this repo

1. **`profiles/M.json` passes no `--mtp`.** `--spec` only sizes the verify window; without
   `--mtp <mtp>/rt` no draft layer loads and every draft is rejected. Real-traffic decode:
   **9.6 tok/s without it, ~27 tok/s with it**, same output tokens.
2. **`--expert-cache auto` is not reproducible.** It sizes from whatever VRAM is free at start: the same
   config produced 2,688 slots on one start and 1,719 on the next. Pin it
   (`--expert-cache 2688 --expert-cache-per-layer`).
3. **`--parallel 2` costs 0.94 GiB of expert-cache VRAM** (`the slot sessions take 0.94 GiB of VRAM on
   CUDA0 that the expert cache would otherwise hold`). With one user, `--parallel 1` returns ~750 slots.
4. **The drafter costs 945 MiB of VRAM** (820 draft layer + 125 draft head) and is clearly worth it.
5. **`--resident-budget-gib 12` is strictly dominated**: same decode as 8 GiB but 3.5 s slower to start.

## Measured

Config: 128K context, `--kv q4_0`, `--kv-resident 20480`, `--resident-budget-gib 16`,
`--expert-cache 2688 --expert-cache-per-layer`, `--prefill auto`, `STRATA_FILE_SKIP=3`,
`STRATA_ROUTE_TAIL_SKIP=6`, drafter on, one slot.

| what | number |
| --- | --- |
| decode, real chat traffic | 26–28 tok/s |
| decode, predictable continuation | 21.9 tok/s (52% draft acceptance) |
| decode, drafter off | 9.6 tok/s |
| prefill | ~25 tok/s |
| time to first token | ~20 s (dominated by the 16 GiB resident copy, ~0.75 s/GiB) |
| expert-cache hit rate | 65–85% |
| VRAM | ~10.6 of 12.3 GB |

## Limits

- **Not tested on Blackwell.** v0.2.2's `uint16_t` TQ2_T reads are kept over the patch's byte-load
  workaround; the target here is sm_89.
- **`tq_avx512.cpp` compiles but never ran** — this CPU has no AVX-512. `tq_cpu_parity` passes
  bit-for-bit for scalar and AVX2 against ggml-cpu's `vec_dot` (~1e-7 relative).
- HIP, Metal and SYCL were not built.
- 128K context is what fits comfortably here; the GyroStrata profile's 256K moves the KV to pinned RAM and
  costs ~1.3 GiB of cache slots.
